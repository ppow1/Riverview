# RV-018.5 corrective evidence — explicit extension contract

## Assessment

The earlier RV-018.5 evidence was partial: bounded service/provider/control
contracts existed, but there was no explicit machine-readable module identity,
compatibility check, lifecycle declaration, or graphable extension boundary.
It is retained as historical evidence and is not rewritten.

This corrective evidence adds the minimum core-freeze seam:

- `src/riverview/modules/contracts.py` defines the versioned manifest contract;
- `src/riverview/modules/registry.py` validates identity, duplicate modules, and
  incompatible core contracts fail closed;
- `config/modules/operator.json` and `config/modules/reasoning_ollama.json`
  prove two real extension declarations;
- `docs/architecture/RIVERVIEW_MODULE_CONTRACT_V1.md` defines core ownership,
  event/action/projection/provider/UI/diagnostic/configuration/lifecycle/storage
  and authority surfaces;
- `docs/architecture/riverview_system_graph.json` derives module dependency and
  checkpoint edges from the manifests and bounded core contract annotations.

## Remaining boundary

This is a contract and registry proof, not a claim that every existing source
file has already been physically migrated into a module package. Future
extensions must use the declared surfaces and must not add kernel authority or
private cross-module coupling.

## Verification

`tests/test_modules_and_graph.py` validates manifest loading, secret-free
declarations, fail-closed compatibility, graph endpoints, and checkpoint links.
