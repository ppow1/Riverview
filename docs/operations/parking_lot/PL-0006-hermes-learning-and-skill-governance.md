# PL-0006 — Hermes Learning and Skill Governance

## Purpose

Maintain a small durable hit list for questions about Hermes native learning,
profile/user observations, skill lifecycle, model promotion, and overlap with
future Honcho experiential memory.

## Current authorization and boundary

Tranche 2 authorizes investigation and documentation only. This item does not
authorize a new personalization system, resident activation, canonical resident
writes, hosted memory, or automatic promotion of learned procedures.

## Hit list

1. What did Hermes's self-improvement review actually learn about Pat/the
   Steward, and where is that observation stored?
2. Where does Hermes store learned user-profile information, and can each item
   be edited, rejected, expired, or audited?
3. Can learning be scoped between Pat, Jessica, Grace, and other individual
   residents without conflating implementation profiles with occupants?
4. How should future local Honcho conclusions overlap with Hermes native user
   profile and memory observations?
5. Which resident-related learned conclusions require Jessica's review as Chief
   Character Architect before use?
6. How are skills versioned, reviewed, promoted, pinned, archived, retired, and
   rolled back?
7. How are mistaken procedural skills corrected, and how is skill drift detected
   when a repository or lifecycle contract changes?
8. How should large-project 900K model selection be automated without making a
   session-scoped implementation choice global or authoritative?
9. Can session-scoped model promotion become a reviewed procedural policy, and
   what evidence should gate it?
10. How should self-improvement reports distinguish a useful reusable procedure
    from a one-tranche anecdote?

## Safe interim rule

Hermes skills, memories, sessions, model selections, and profiles remain
procedural/evidence carriers. They do not become Riverview authority, resident
canon, Campaign Runner lifecycle state, Living Diagnostics truth, or acceptance
without explicit institutional promotion.

## Promotion condition

Promote for elaboration when a concrete learning/skill governance change is
needed and the Steward commits to its scope, evidence, and acceptance basis.
